## Lacunas (L), conflitos (C) e decisões de precedência

| ID | Tipo | Descrição | Ação |
|---|---|---|---|
| L-01 | Lacuna de dados | O modelo **não guarda data, horário nem local** de uma rodada (`planned_lineups` só tem rótulo/times). E04 exige esses dados "quando oficialmente disponíveis". O local padrão da pelada (`peladas.location`, REV-006) existe, mas não é o local de uma rodada específica e **não foi usado**. | A UI mostra data/horário/local se `scheduled_at`/`location` vierem; hoje não vêm. Criar agendamento de rodada é funcionalidade nova → **exige aprovação**. |
| L-02 | Decisão técnica a confirmar | O anexo não lista **quais** estatísticas são "da posição". Foram usados só contadores oficiais já existentes (gols, assistências, gols sofridos do placar, defesas difíceis registradas; Jogos/Vitórias/Empates/Derrotas). Não existem totais de carreira de defesas, desarmes etc. | Mapeamento em `lib/v84logic.ts`; confirmar com o fundador. |
| L-03 | Lacuna de dados | "Finanças privadas" na Atenção: não existe RPC de pendência financeira do **jogador** (só do administrador). Nada foi inventado. | Quando existir a fonte oficial, entra com `rank` 3. |
| L-04 | Não implementado (risco) | E09/E15-18: pilhas e rolagem **independentes por aba** exigem mover ~45 rotas para grupos compartilhados do Expo Router e reescrever os caminhos absolutos; sem dispositivo/sessão real não há como validar. Hoje as telas internas abrem sobre a pilha raiz (decisão V4.6). | **Exige aprovação + teste em dispositivo.** Mitigação parcial: `backBehavior="history"`, toque repetido na aba Início. |
| L-05 | Não verificável | Histórico de ex-integrantes sem pelada ativa (E11): o feed de notificações mantém avisos de `left`; a Central mostra só peladas ativas. | Auditar com dados reais. |
| L-06 | Limitação | Não existe identificador de "versão de publicação" compartilhado entre blocos; cada bloco lê o estado atual. Divergência momentânea entre blocos é possível e hoje não é sinalizada. | Exige contrato do servidor. |
| C-01 | Conflito documental | REV-028 (V8.0) pedia resumo de pendências administrativas **na Central**; E07 (posterior e específica) o exclui. **Precedência: E07 no bloco Atenção.** O resumo administrativo não foi reposto em outro lugar da Central; os dados continuam em `pelada/[id]` (`AdminPending`). | Reconciliar se o fundador quiser o resumo de volta. |
| C-02 | Observação | A migração única da pelada escolhida só no aparelho (AsyncStorage) para o servidor (`set_primary_pelada`) é a única escrita feita sem toque do usuário; preserva a escolha anterior. | Registrada. |
| C-03 | Mudança visual global | `Card` compartilhado passou de cinza-claro sem borda (V6.2) para branco com borda e sombra leve, raio 14→16 (E10/Entrega B). | Ver `V8.4_PADRONIZACAO_GLOBAL.md`. |
